# Security reports

[한국어](SECURITY.ko.md)

Please send suspected vulnerabilities privately to [support@pcssak.com](mailto:support@pcssak.com), with “Palette security” in the subject. Do not post exploit details, credentials or affected user files in public issues. This email route does not promise end-to-end encryption; see [PRIVACY.md](docs/PRIVACY.md). If a sensitive sample is necessary, first ask how to transfer the minimum safely.

Useful details are the source commit or app version, Windows version and architecture, expected impact, and a minimal reproduction using synthetic data. Omit personal paths, names, customer images and unrelated logs. Do not test systems or accounts you do not control.

This is a one-person project, not a staffed incident-response service. Reports are reviewed according to impact and available capacity; no response deadline, bug-bounty payment or legal safe-harbor promise is offered. Contact us before beginning work for which you expect payment. Please coordinate publication of technical exploit details while a report is being assessed.

Current reports about the public snapshot are welcome. Old versions are not promised indefinite security maintenance; fixes require a reviewed source update and, separately, an appropriately validated release.

Source publication and a clean scanner result are not proofs of safety. Source builds may be unsigned and do not use the official updater by default. Verify the origin and available checksums, keep backups, and do not disable Defender, SmartScreen or other security controls. Never include production signing keys in a fork, issue, log or pull-request workflow.
